# Приёмка квартиры — офлайн-приложение

Мобильное веб-приложение (PWA) для специалистов по приёмке квартир. Работает без интернета и без сервера: все осмотры и фото хранятся в памяти телефона (IndexedDB). Акт формируется прямо на телефоне в Word (.docx) и PDF.

## Что умеет

- Список осмотров, у каждого: объект, номер квартиры, дата, собственник, представитель застройщика, специалист, заключение.
- Характеристики объекта (по галочке в «Данных осмотра»): вид отделки, покрытия стен и пола и т. п., по строке на характеристику. В акте выводятся блоком перед замечаниями.
- Замечания по помещениям: помещение, конструктив, критичность (критичный / значительный / малозначительный), описание, ссылка на норматив, фото.
- Быстрые формулировки типовых дефектов для каждого конструктива.
- Фото с камеры или из галереи, автоматически сжимаются до 1600 px.
- Всё сохраняется автоматически при каждом изменении.
- Акт в Word (таблица с фото, можно править) и PDF (готов к отправке). Кнопка «Отправить» открывает меню «Поделиться» (WhatsApp, Telegram, почта).

## Состав

| Файл | Назначение |
|---|---|
| `index.html` | Всё приложение: интерфейс, хранение, генерация DOCX и PDF. |
| `norms.js` | Справочник нормативов и ключевых слов для автоподбора. Можно дополнять — формат описан в начале файла. |
| `vendor/qrcode.min.js` | Генератор QR-кодов ([qrcode-generator](https://github.com/kazuhikoarase/qrcode-generator) 1.4.4, MIT). Работает офлайн. |
| `sw.js` | Service worker — кэширует приложение для работы офлайн и доставляет обновления. |
| `bump-version.sh` | Поднимает номер версии в `sw.js` и `index.html`. |
| `manifest.webmanifest` | Название, иконка, полноэкранный режим при установке. |
| `icon-192.png`, `icon-512.png` | Иконки. |

## Шаблон акта

Кнопка-шестерёнка на главном экране → «Шаблон акта». Там задаются:
- реквизиты компании — название, телефон, email, сайт, адрес;
- логотип (из галереи, прозрачный фон сохраняется);
- QR-код: визитка компании (при сканировании телефон предлагает сохранить контакт), телефон, сайт или свой текст; подпись под QR;
- заголовок, подзаголовок и типовые заключения акта.
- свои конструктивы (например «Фасад», «Балконное остекление») — их порядок и удаление. Добавить конструктив можно и прямо из формы замечания: поле «Другой конструктив…» под списком.

Логотип, реквизиты и QR выводятся в шапке первой страницы Word и PDF, название компании — в колонтитуле. Кнопки «Пример PDF» и «Пример Word» формируют акт на тестовых данных, чтобы проверить вид. Шаблон хранится на телефоне; у каждого сотрудника он настраивается отдельно.

## Автоподбор нормативов

Пока сотрудник пишет описание дефекта, приложение ищет в нём ключевые слова (с учётом выбранного конструктива) и подставляет норматив в поле «Норматив». Ниже поля показываются все подходящие варианты с допусками — нажатием их можно добавить или убрать. Если вписать норматив вручную, автоподстановка для этого замечания отключается; если очистить поле — включается снова.

Источники (сверены на октябрь 2026 г.):
- **Приказ Минстроя России от 19.02.2025 № 91/пр** — минимальные требования к отделке на объектах долевого строительства (пп. 1–17 приложения);
- **ГОСТ Р 72509-2026** «Отделочные работы. Требования к результатам работ» (с 01.03.2026, табл. 5.1–5.12);
- окна — ГОСТ 30971-2012, ГОСТ 30674-2023, ГОСТ 23166-2024, ГОСТ 24866-2014; двери — ГОСТ 475-2016, ГОСТ 31173-2016;
- инженерные системы — СП 30.13330.2020, СП 73.13330.2016, СП 60.13330.2020, СП 256.1325800.2016, ПУЭ.

СП 71.13330.2017 для отделки не используется: требования к отделочным работам исключены из него Изменением № 3 с 01.02.2026.

В «Шаблоне акта» → «Нормативы» можно выключить автоподбор и выбрать, на что ссылаться по отделке: на приказ, на ГОСТ Р или на оба. Справочник правил — в `norms.js`.

## Как запустить на телефонах

Приложение нужно один раз разместить на любом статическом хостинге с HTTPS (без HTTPS офлайн-режим не включится). Бэкенд не нужен — это просто файлы.

Самый простой вариант — **GitHub Pages**:
1. Создайте репозиторий, загрузите в него все файлы из этой папки.
2. Settings → Pages → Branch: `main`, папка `/ (root)` → Save.
3. Через минуту приложение будет доступно по адресу `https://<логин>.github.io/<репозиторий>/`.

Подойдут также Netlify, Cloudflare Pages, Яндекс Object Storage или ваш корпоративный веб-сервер.

**Установка у сотрудника** (нужен интернет только в первый раз):
- Android (Chrome): открыть ссылку → меню ⋮ → «Добавить на главный экран» / «Установить приложение».
- iPhone (Safari): открыть ссылку → «Поделиться» → «На экран „Домой“».

Дальше приложение запускается с иконки и работает без сети.

## Важно знать

- Данные хранятся только на этом телефоне. Если удалить приложение или очистить данные браузера — осмотры пропадут. Готовые акты стоит сразу отправлять.
- На iPhone данные приложения, установленного на экран «Домой», хранятся отдельно от Safari.
- PDF формируется как изображения страниц (текст в нём не выделяется), зато кириллица и фото выглядят одинаково на любом устройстве. Для правок используйте Word.

## Версии и обновление

Версия состоит из трёх чисел — **мажорная.минорная.патч**, например `0.0.2`. Текущая версия видна внизу списка осмотров.

Как выпустить обновление:
1. Внесите изменения.
2. Поднимите версию:
   - `./bump-version.sh patch` — исправление ошибок (0.0.2 → 0.0.3)
   - `./bump-version.sh minor` — новая функция (0.0.3 → 0.1.0)
   - `./bump-version.sh major` — крупное изменение (0.1.0 → 1.0.0)
3. Закоммитьте и выложите на хостинг (`git push`).

На телефоне приложение проверяет обновления при запуске, при каждом возврате в него и раз в 30 минут (если есть интернет). Новая версия скачивается в фоне, и сверху появляется плашка «Доступна новая версия — Обновить». Сотрудник нажимает её, когда ему удобно; введённые данные перед перезагрузкой сохраняются. Пока не нажал — работает прежняя версия.

Номер версии не меняйте руками: если поменять код без новой версии, телефоны обновление не получат.

## Как доработать

- Справочники помещений, конструктивов и типовых формулировок — в начале скрипта в `index.html` (`ROOMS`, `CATS`, `PHRASES`).
- Шапка и подписи акта — функции `buildDocx` и `buildPdf`.
- Если понадобится приложение из магазинов (Google Play / App Store), эти же файлы можно обернуть в нативную оболочку через Capacitor без переписывания.
